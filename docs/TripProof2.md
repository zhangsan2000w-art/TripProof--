## 项目初步想法

**项目名称：TripProof《攻略压力测试》。**

用户已经收藏了一份旅行攻略，准备订票或出发，但不知道这份攻略在自己的日期、起点和条件下是否走得通。用户上传攻略截图或粘贴文字，系统核对其中的活动安排，提前发现闭馆、入场时段、交通衔接或天气条件等问题，并给出有出处的解释和调整建议。

主要面向已经有行程、即将付费或出发的人，例如周末短途出游者、家庭出游组织者，以及第一次去陌生城市的游客。

希望实现的核心体验：

1. 从截图或文字中识别日期、地点、活动和时间顺序，允许用户校对。
2. 使用赛道合作检索工具，对影响行程的关键条件逐项查证。
3. 将结果分为**可确认 / 存在冲突 / 尚无法确认**，展示原因、原始来源和查询时间。
4. 说明关键问题可能影响哪些后续安排，并给出尽量少改动原行程的建议。
5. 保留真实检索过程与证据，能够形成符合赛事要求的查询材料和调查报告。

例如，一份两日行程安排某天上午参观博物馆。系统查到适用于该日期的闭馆规则，并核对临时开放例外后，指出对应安排的冲突，让用户打开原始公告，同时说明哪些后续活动需要重新确认。该例仅用于说明产品想法，实际案例和结论需要通过真实查询获得。

对于实时余票、预约库存、无法核实的班次或天气条件，应明确说明信息边界，保留“尚无法确认”。

希望优先体现**截图查证和深度调查**；变化监控可以根据开发成本决定是否纳入。
