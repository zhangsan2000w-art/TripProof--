# TripProof Agent 升级验收

验收日期：2026-10-24，Asia/Shanghai。环境：macOS、Node.js 26.12.1、pnpm 12.14.0、Next.js 16.4.2、Chrome。模型沿用现有中转的 `gpt-6.1-sol` Responses 结构化输出；搜索为真实元宝 SearchPro standard。

## 交付行为

确认攻略后进入对话与行程工作台。模型选择白名单工具，服务端校验参数、读取来源，再由代码核对日期、开放、预约和衔接。对话、行动、证据缺口、停止原因、问题、预算和预览均持久化。普通追问与修复试算不联网；明确复查才增加搜索。修改先展示预览，用户应用后增加行程版本。

保留最多 12 轮行动决策、40 次实际搜索、每场馆 5 次、搜索并发 4、8 分钟活动时间限制。等待回答释放 worker，回答后续接同一个任务，不重置预算；成功工具步骤不会在恢复后重新执行。相同检查连续两轮没有有效新证据即停止。天气与区域公告并行，必要检查没有完成时汇总显示“仍在核验”。

替代场馆最多两个，独立调查后存为候选；`replace` 只能引用已存的同城候选，保留原安排对照并标注 Agent 建议。预览同时绑定行程版本、证据指纹和重新计算结果，过期应用返回 409。新接口及错误语义见 [AGENT-API.md](AGENT-API.md)。

## 浏览器与数据保留

Chrome 桌面与 390×844 手机视口实际验收：对话、行程、证据分区切换；原生日期/时间编辑；调查中补充要求；取消后证据保留；刷新和服务重启后恢复；分享；反馈写入 SQLite；公开报告不包含私人对话。手机 `documentElement.scrollWidth=390`，没有横向溢出。

旧修复预览因证据或重算变化被拒绝；拒绝提示现放在预览弹窗内。重新预览雷峰塔 16:00—17:00，直接下一站西湖 12:00 被标为需调整，其他后续站不被连带判冲突。正常 11:00—11:30 预览由用户应用后，版本增加，刷新仍保留，没有新增搜索。换日期预览未自动应用，也不搜索。

另一次真实对话要求核查闭馆后的替代方案：Agent 自主调用 `find_alternatives`，5 次实际搜索后保存杭州博物馆 23 条独立事实，并生成仅引用已存候选 ID 的 `replace` 预览。预览把原博物馆的闭馆冲突从 1 降为 0，保留六站顺序和其他时段，没有自动应用；随后人工点击应用并刷新，六站行程及版本持久化。替换项在预览、工作台和报告均明确标注“Agent 建议”。产物在本地 `artifacts/agent-browser/alternatives.json`。

本地 3000 密码锁定/解锁通过；用户原历史报告可打开；杭州、临安、南京、洞头四个首页 demo 清单与升级前逐字一致，`data/sample-reports.json` 未替换。截图保存在本地 `artifacts/agent-browser/`。

## 发布与边界

全部应提交源码、测试和文档纳入 `main`，通过部署白名单同步 GitHub `modelscope` 分支及魔搭 `master`，不强推。发布操作与运行源码核对见 [MODELSCOPE-DEPLOYMENT.md](MODELSCOPE-DEPLOYMENT.md)。上线必须以 `/api/health.sourceCommit` 对比源 `main` 的 SHA，不能只看分支推送成功。

源码、104 个部署包文件与 1685 个 standalone 构建文件已扫描，没有发现实际密钥、环境文件、本地数据库或原始输入进入部署产物。原始输入、运行数据库、缓存、实际调用 JSON 与截图保存在本地，不提交或公开私人对话。

当前仍有明确限制：实时库存、实际交通可达性、超范围预报和无法裁决的来源矛盾保留未知；完整调查性能仍未达标。魔搭外层手机 iframe 的历史截断问题需上线后单独复核，应用本地响应式通过不能证明平台适配通过。通用 Compose/Caddy 未在 VPS 实测，本机无 Docker；魔搭镜像的构建及启动由实际平台验收。
